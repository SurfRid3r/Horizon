## [Vertex AI Python SDK 漏洞可实现跨租户远程代码执行](https://unit42.paloaltonetworks.com/hijacking-vertex-ai-model/) ⭐️ 9.0/10

Palo Alto Networks 的 Unit 42 披露了 Google Cloud Vertex AI Python SDK 中的一个严重漏洞，该漏洞通过 bucket squatting 技术实现跨租户远程代码执行。该缺陷使攻击者能够预先抢占 SDK 在模型上传过程中使用的云存储桶名称，从而劫持上传流程并投递恶意载荷。 该漏洞暴露了最广泛使用的托管机器学习平台之一的严重攻击面，威胁到基于云的机器学习基础设施的完整性和隔离性。它凸显了机器学习供应链和 SDK 默认配置可能成为严重跨租户入侵的攻击媒介，影响所有依赖 Vertex AI 运行生产工作负载的组织。 该攻击利用了 Vertex AI SDK 在暂存模型工件时使用的可预测存储桶命名模式，结合了 Python pickle 序列化格式在反序列化不受信任数据时的固有不安全性。通过在合法用户之前注册目标存储桶名称，攻击者可以提供恶意 pickle 载荷，当受害者加载模型时即会执行任意代码。

rss · Unit 42 · 6月16日 10:00

**背景**: Bucket squatting 是一种云安全漏洞，威胁行为者预先注册目标组织可能使用的云存储桶名称，从而拦截数据或冒充服务。Google Cloud Vertex AI 是一个完全托管的端到端机器学习平台，提供用于数据摄取、模型训练和部署的 SDK。Python 的 pickle 格式通常用于序列化机器学习模型对象，但加载不受信任的 pickle 文件是一个众所周知的安全风险，因为反序列化可能触发任意代码执行。跨租户 RCE 攻击在云环境中尤其危险，因为它们破坏了云提供商在不同客户之间保证的逻辑隔离。

## [同济大学毕业演讲透露国产 7nm ArF 浸没式光刻机交付中芯国际](https://news.tongji.edu.cn/info/1002/94903.htm) ⭐️ 9.0/10

在同济大学的一场毕业演讲中，透露由贺荣明团队研发的首台国产氟化氩浸没式光刻机已于 2025 年 5 月正式交付给中芯国际。该设备结合多重曝光工艺，能够稳定支撑 7 纳米及以上制程的芯片生产。 这一交付标志着中国在高端前道光刻设备领域取得了重大突破，有效打破了国外厂商（如 ASML）的长期垄断。它证明了相关技术正从实验室原型走向实际的工业部署，这是中国在全球科技摩擦背景下实现半导体自立自强的关键一步。 ArF 浸没式光刻机采用 193 纳米的光源，并依赖复杂的多重曝光技术来实现 7 纳米的分辨率，这已经达到了 DUV 技术的物理极限。有趣的是，提及这一成就的毕业演讲相关段落据称已从大学的官方记录中被移除，突显了该突破背后的政治敏感性。

telegram · zaihuapd · 6月16日 16:34

**背景**: 光刻机是半导体制造中最关键的设备，负责将电路图案投射到硅片上。深紫外（DUV）光刻机，特别是 ArF 浸没式系统，使用 193 纳米的光源，并在镜头和硅片之间引入液体介质以提高分辨率。尽管目前 7 纳米等先进节点的主流标准是 EUV 光刻机，但使用 DUV 技术达到该节点需要采用极其复杂且成本高昂的多重曝光工艺。

## [关于本地模型可用性的博文引发技术讨论](https://vickiboykis.com/2026/06/15/running-local-models-is-good-now/) ⭐️ 8.0/10

Vicki Boykis 发布的一篇博文声称，在本地运行 AI 模型已经变得真正可行，并在 Hacker News 上引发了关于实际权衡的激烈讨论。争论的焦点在于，像 Qwen、Gemma 这样的开源大语言模型是否能在智能体编程等实际任务中真正与云端模型匹敌。 这场讨论凸显了 AI 行业的一个关键转折点：随着本地模型的不断改进，它们正在威胁 Anthropic 和 OpenAI 等云端 AI 供应商的定价能力。辩论还揭示了用户期望的深度分化——对于什么才算"足够好"可以实际使用，目前尚无共识。 社区成员指出，量化（通常是 4-bit）会显著降低工具调用能力，在内存效率与模型能力之间制造了矛盾。像 Qwen 27B 这样的稠密模型聪明但速度慢，而像 Gemma 26B 这样的 MoE 模型速度快但容易出错，没有哪种架构能取得明显优势。

hackernews · jfb · 6月16日 14:36 · [社区讨论](https://news.ycombinator.com/item?id=48555993)

**背景**: 量化是一种降低模型参数数值精度的技术，使大模型能够在内存较少的消费级硬件上运行，但会牺牲一定的准确率。本地大语言模型的运动在 2023 年获得动力，当时 llama.cpp 和 GGUF 格式使得在消费级 CPU 和 GPU 上运行有能力的模型变得切实可行。MoE（混合专家）架构每个 token 只激活部分参数，以知识广度换取速度，而稠密模型激活全部参数，质量更高但推理速度更慢。

## [GitHub 启动向微软 Azure 服务器的分阶段迁移](https://t.me/zaihuapd/41980) ⭐️ 8.0/10

GitHub 宣布将在未来 12 个月内分阶段迁移至微软 Azure 服务器，并计划在两年内完全脱离自有数据中心。首席技术官 Vladimir Fedorov 向员工宣布了这一决定，理由是数据中心容量面临限制，尤其是在北弗吉尼亚地区扩容机会有限。 这是前 CEO Thomas Dohmke 两个月前辞职以来 GitHub 的首个重大战略变化，标志着被微软收购后更深层次的基础设施整合。这一举措影响全球数百万依赖 GitHub 平台的开发者，也代表了微软云战略中重要的整合步骤。 此次迁移是由现有数据中心具体的容量瓶颈所驱动的，北弗吉尼亚被指明为扩容的痛点区域。Fedorov 在内部备忘录中将这一举措描述为必须而非可选，表明基础设施挑战的紧迫性。

telegram · zaihuapd · 6月16日 06:06

**背景**: 微软于 2018 年以 75 亿美元收购了 GitHub，但此后 GitHub 一直独立运营自己的数据中心。Azure 是微软的旗舰云计算平台，提供基础设施即服务和平台即服务。北弗吉尼亚是全球最大的数据中心集群之一，但由于 AI 和云计算工作负载激增，其容量正日益紧张。
