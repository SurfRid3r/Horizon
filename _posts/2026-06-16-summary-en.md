## [Vertex AI Python SDK Vulnerability Enables Cross-Tenant RCE](https://unit42.paloaltonetworks.com/hijacking-vertex-ai-model/) ⭐️ 9.0/10

Palo Alto Networks' Unit 42 disclosed a critical vulnerability in the Google Cloud Vertex AI Python SDK that allows cross-tenant remote code execution through bucket squatting. The flaw enables attackers to preemptively claim cloud storage bucket names that the SDK uses during model uploads, hijacking the upload process to deliver malicious payloads. This vulnerability exposes a serious attack surface in one of the most widely used managed machine learning platforms, threatening the integrity and isolation of cloud-based ML infrastructure. It underscores that ML supply chains and SDK defaults can become vectors for severe cross-tenant compromises, affecting any organization relying on Vertex AI for production workloads. The attack exploits the predictable bucket naming pattern used by the Vertex AI SDK when staging model artifacts, combined with Python's pickle serialization format, which is inherently unsafe when deserializing untrusted data. By registering the target bucket name before a legitimate user, an attacker can serve a malicious pickle payload that executes arbitrary code when the victim loads the model.

rss · Unit 42 · Jun 16, 10:00

**Background**: Bucket squatting is a cloud security vulnerability where threat actors preemptively register cloud storage buckets with names that target organizations are likely to use, allowing them to intercept data or impersonate services. Google Cloud Vertex AI is a fully managed, end-to-end machine learning platform that provides SDKs for data ingestion, model training, and deployment. Python's pickle format is commonly used to serialize ML model objects, but loading untrusted pickle files is a well-known security risk because deserialization can trigger arbitrary code execution. Cross-tenant RCE attacks are especially dangerous in cloud environments because they breach the logical isolation that cloud providers guarantee between different customers.

## [Tongji University Speech Reveals Domestic 7nm ArF Immersion Lithography Machine Delivered to SMIC](https://news.tongji.edu.cn/info/1002/94903.htm) ⭐️ 9.0/10

During a graduation speech at Tongji University, it was revealed that China's first domestically developed ArF immersion lithography machine, led by He Rongming's team, was officially delivered to SMIC in May 2025. Utilizing multi-patterning technology, the equipment can support the production of 7nm process nodes. This delivery marks a monumental breakthrough for China in the high-end front-end lithography equipment sector, effectively breaking the long-standing foreign monopoly held by companies like ASML. It demonstrates a transition from laboratory prototypes to actual industrial deployment, which is a critical step for China's semiconductor self-sufficiency amidst global tech tensions. The ArF immersion lithography machine utilizes a 193nm light source and relies on complex multi-patterning techniques to achieve 7nm resolution, pushing the physical limits of DUV technology. Interestingly, the sections of the graduation speech mentioning this achievement were reportedly removed from the university's official records, highlighting the political sensitivity surrounding the breakthrough.

telegram · zaihuapd · Jun 16, 16:34

**Background**: Lithography machines are the most critical equipment in semiconductor manufacturing, responsible for projecting circuit patterns onto silicon wafers. Deep Ultraviolet (DUV) lithography, specifically ArF immersion systems, uses a 193nm light source and introduces a liquid medium between the lens and the wafer to enhance resolution. While EUV is the standard for advanced 7nm nodes today, reaching this node with DUV requires highly complex and costly multi-patterning processes.

## [Blog Post on Local Model Viability Sparks Technical Debate](https://vickiboykis.com/2026/06/15/running-local-models-is-good-now/) ⭐️ 8.0/10

A blog post by Vicki Boykis asserted that running local AI models has become genuinely viable, sparking an intense community discussion on Hacker News about the practical trade-offs. The debate centered on whether open-source LLMs like Qwen, Gemma, and others can truly rival cloud-based models for real-world tasks such as agentic coding. This discussion highlights a critical inflection point in the AI industry: as local models improve, they threaten the pricing power of cloud AI providers like Anthropic and OpenAI. The debate also reveals deep fragmentation in user expectations, with no consensus on what qualifies as 'good enough' for practical use. Community members noted that quantization (typically 4-bit) degrades tool-calling performance significantly, creating a tension between memory efficiency and capability. Dense models like Qwen 27B are intelligent but slow, while MoE models like Gemma 26B are fast but error-prone, with no architecture offering a clear win.

hackernews · jfb · Jun 16, 14:36 · [Discussion](https://news.ycombinator.com/item?id=48555993)

**Background**: Quantization is a technique that reduces the numerical precision of model parameters, allowing large models to run on consumer hardware with less memory, but at the cost of some accuracy. The local LLM movement gained momentum in 2023 when llama.cpp and the GGUF format made it practical to run capable models on consumer-grade CPUs and GPUs. MoE (Mixture of Experts) architectures activate only a subset of parameters per token, trading breadth of knowledge for speed, while dense models activate all parameters, offering higher quality but slower inference.

## [GitHub Begins Phased Migration to Microsoft Azure Servers](https://t.me/zaihuapd/41980) ⭐️ 8.0/10

GitHub has announced a phased migration to Microsoft Azure servers over the next 12 months, with plans to fully exit its own data centers within two years. CTO Vladimir Fedorov communicated this decision to employees, citing data center capacity constraints, particularly limited expansion opportunities in Northern Virginia. This is the first major strategic change at GitHub following former CEO Thomas Dohmke's resignation two months ago, signaling deeper infrastructure integration with Microsoft post-acquisition. The move affects millions of developers worldwide who rely on GitHub's platform, and it represents a significant consolidation step in Microsoft's cloud strategy. The migration is driven by concrete capacity bottlenecks at GitHub's existing data centers, with Northern Virginia identified as a particular pain point for expansion. Fedorov's internal memo framed the move as essential rather than optional, indicating the urgency of the infrastructure challenge.

**Background**: Microsoft acquired GitHub in 2018 for $7.5 billion, but GitHub has continued operating its own data centers independently since then. Azure is Microsoft's flagship cloud computing platform, providing infrastructure-as-a-service and platform-as-a-service offerings. Northern Virginia is one of the world's largest data center hubs, but its capacity has been increasingly strained by surging demand from AI and cloud computing workloads.
