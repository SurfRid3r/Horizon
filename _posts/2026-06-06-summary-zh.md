## [英伟达拟为 Windows PC 开发高性能 ARM 架构 CPU](https://twitter.com/lemire/status/2062880075117113739) ⭐️ 8.0/10

据报道，英伟达正在为 Windows PC 开发一款采用统一内存架构的高性能 ARM 架构 CPU 系统。这一潜在的突破旨在为 Windows 生态系统带来类似苹果芯片的强大功能和紧密的硬件集成。 这一发展可能会通过挑战英特尔和 AMD 来显著颠覆 PC 处理器市场，同时为苹果大获成功的 M 系列芯片提供强有力的替代方案。统一内存架构将特别有利于 Windows 设备上的本地 AI 工作负载和高效能计算。 尽管拟议中的系统在共享内存池下结合了 CPU 和 GPU 的功能，但批评者指出，与独立显卡相比，共享的热量限制（TDP）和降低的内存带宽可能会限制 GPU 的性能。英伟达将如何平衡高端游戏需求与 ARM 架构固有的能效，还有待观察。

hackernews · tosh · 6月6日 12:52 · [社区讨论](https://news.ycombinator.com/item?id=48424605)

**背景**: 统一内存架构（UMA）允许 CPU 和 GPU 共享相同的内存池，从而无需来回复制数据，并显著降低 AI 处理等数据密集型任务的延迟。苹果在其 M 系列芯片中成功利用了这一架构，为性能和电池续航树立了新的行业标准。同时，Windows on ARM 在应用程序兼容性和性能开销方面一直存在历史性的困难，尽管微软已稳步改进其 x86 和 x64 仿真层以支持更广泛的旧版应用程序。

## [系统编程正寻求超越传统的 Unix fork() 与 exec()](https://lwn.net/SubscriberLink/1076018/16f01bbbb8e0d1f0/) ⭐️ 8.0/10

LWN.net 上的一篇最新文章在系统编程社区引发了新一轮讨论，探讨了传统 Unix fork() 和 exec() 系统调用的历史局限性与性能开销。该文章强调了现代操作系统和开发者正如何越来越多地转向使用替代 API 来创建进程。 进程创建是计算中的基本操作，重新评估这种诞生于 20 世纪 70 年代的设计能够为现代软件带来显著的性能提升和更好的线程安全性。摆脱这一遗留标准有助于减少与进程状态管理相关的复杂错误，并使系统编程更好地适应现代硬件能力。 讨论的主要技术问题在于 fork() 会复制整个进程状态，当紧接使用 exec() 加载新程序时，这种操作会变得极其低效。尽管写时复制优化缓解了内存复制的开销，但在子进程中管理文件描述符和多线程状态等元素依然是一项复杂且容易出错的任务。

hackernews · jwilk · 6月6日 14:34 · [社区讨论](https://news.ycombinator.com/item?id=48425528)

**背景**: 在类 Unix 操作系统中，新进程传统上是通过两步机制创建的。fork() 系统调用会创建一个与调用进程完全相同的副本，而 exec() 函数则用新程序替换该新进程的内存空间。尽管 POSIX 标准要求支持这一组合机制，但由于其在处理大型、内存密集型进程时性能不佳以及固有的线程安全问题，fork() 近年来已逐渐失宠。
