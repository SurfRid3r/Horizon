## [发现 WordPress 未授权 RCE 利用链 (wp2shell)](https://lorexxar.cn/2026/07/24/wp2shell/) ⭐️ 9.0/10

WordPress 中披露了一个名为 "wp2shell" 的严重未授权远程代码执行（RCE）漏洞，影响版本从 6.9.0 到 7.0.1。该利用巧妙地将两个独立的漏洞（CVE-2026-63030 和 CVE-2026-60137）组合在一起，涉及 REST API 批处理路由混淆和基于时间的 SQL 注入。 该漏洞对超过 5 亿个使用 WordPress 的网站构成了重大安全威胁，特别是自 5.0 版本以来，该平台被认为能有效防止此类未授权漏洞。此外，有传言称该利用链是通过 AI 发现的，并获得了 50 万美元的赏金，这突显了 AI 工具在加速漏洞发现和进攻性网络安全方面的变革性影响。 初始入口点通过 REST API 批处理路由混淆链绕过身份验证，从而导致预授权的基于时间的 SQL 注入。即使 PHP 的 `disable_functions` 限制了命令执行，该利用仍可成功创建管理员帐户，但在这些特定的服务器限制下，最终的 RCE 阶段将会失败。

rss · LoRexxar's Blog · 7月24日 07:49

**背景**: 远程代码执行（RCE）允许攻击者在服务器上执行任意恶意代码，通常会导致系统被完全攻破。WordPress 是世界上最受欢迎的内容管理系统（CMS），自 5.0 版本以来以其严格的权限分割和稳健的架构而闻名。利用链（如 wp2shell 方法）涉及将多个较小的漏洞链接在一起，以实现单独无法达成的更大、更具影响力的系统突破。

## [Cloudflare 揭示 BGP ORIGIN 属性被广泛篡改](https://blog.cloudflare.com/bgp-origin-attribute/) ⭐️ 9.0/10

Cloudflare 发布的深度测试结果表明，互联网传输提供商为了获取流量优势，在近 70%的路径中篡改了 BGP ORIGIN 属性。因此，Cloudflare 主张在 BGP 路由选择过程中废弃 ORIGIN 属性。 这一发现突显了互联网核心路由协议在可靠性方面的根本缺陷，影响了全球网络间的流量导向。废弃 ORIGIN 属性可能会推动网络标准的更新，使互联网路由行为更可预测且更安全。 BGP ORIGIN 属性旨在指示路由更新的来源（IGP、EGP 或不完整），并在 BGP 最佳路径选择算法的第 8 步中作为决胜条件。传输提供商为了操纵入站流量而不当修改这一公认强制属性，导致其完全无法发挥预期的作用。

rss · The Cloudflare Blog · 7月24日 17:25

**背景**: BGP（边界网关协议）是维持互联网运行的标准路由协议，它负责在不同的自治系统之间交换路由信息。为了在多个选项中选出最佳路径，BGP 采用严格的决策过程来评估各种属性。ORIGIN 代码是 BGP 公认强制路径属性，用于指定路由最初是如何引入 BGP 的，系统通常优先选择 IGP，其次是 EGP，最后是不完整。

## [某安全摄像头出厂固件中内置了硬编码的 GitHub 管理员 token](https://hhh.hn/hanwha-github-token/) ⭐️ 8.0/10

一名安全研究员发现，韩华（Hanwha）的一款商用安全摄像头的登录页面中直接内置了硬编码的 GitHub 管理 token。此外，该固件中还被发现包含硬编码的美国国防部 IP 地址以及其他令人担忧的不安全默认设置。 这一事件凸显了严重的供应链和运营安全漏洞，攻击者可以利用泄露的 token 访问私有源代码或破坏后端基础设施。它强调了消费级物联网行业中持续缺乏基本安全实践的问题，将用户隐私和网络安全置于巨大的风险之中。 在公开可访问的登录页面上暴露管理 token 意味着，任何扫描该设备的人都可能立即获得对制造商代码仓库的特权访问。此外，将静态 IP 地址和凭据直接硬编码到固件中是一个极其严重的工程反模式，如果没有制造商发布的补丁，这种风险将无法被消除。

hackernews · hhh · 7月24日 11:54 · [社区讨论](https://news.ycombinator.com/item?id=49034292)

**背景**: 硬编码凭据是一种常见但极其严重的漏洞，开发人员会将敏感密钥、密码或 token 直接留在源代码中。像安全摄像头这样的物联网设备通常会处理敏感数据并驻留在本地网络上，使其成为恶意行为者的极具吸引力的目标。采用安全的网络分段（例如将物联网设备放置在没有互联网访问权限的独立虚拟局域网（VLAN）上）是减轻此类硬件缺陷风险的标准防御做法。

AI 模型路由平台 OpenRouter 已被多家大型科技公司接洽，探讨潜在收购可能，意向估值或超过其今年 5 月 B 轮融资后约 13 亿美元的投后估值。平台目前路由超过 400 个模型，服务约 800 万用户，每月处理约 100 万亿个 token。 这标志着 AI 基础设施层正在加速整合，模型路由平台已成为连接模型提供商与终端应用的战略性资产。大型科技公司的潜在收购可能重塑开发者访问和在竞争性大模型之间进行路由的方式，也反映出整个行业 AI 推理需求的巨大规模。 OpenRouter 的 B 轮融资由 Alphabet 旗下 CapitalG 领投，共筹集 1.13 亿美元，投后估值约 13 亿美元，较前一年 6 月 A 轮的 5.47 亿美元翻倍有余。截至 2026 年初，公司年化收入已达约 5000 万美元，每月在其 400 多个模型上处理约 100 万亿个 token。

## [Telegram 悄然修复零点击内存耗尽崩溃漏洞](https://x.com/Fried_rice/status/2080200610985689222) ⭐️ 8.0/10

安全研究人员披露了影响 Telegram 桌面版和 iOS 客户端的零点击内存耗尽漏洞，攻击者可以通过特制消息导致应用崩溃。Telegram 桌面版已针对该问题静默发布了补丁，并且已发布一个测试机器人来演示此漏洞。 该漏洞极其关键，因为攻击者只需发送消息即可破坏广泛使用的平台上的通信，且无需受害者进行任何交互。公开的测试机器人增加了威胁的紧迫性，使得用户立即更新客户端以防止拒绝服务攻击变得至关重要。 该漏洞利用通过特制消息触发内存耗尽（OOM）状态，迫使 Telegram 客户端耗尽可用内存并崩溃。研究人员发布了一个实用的测试机器人 @kimifuckingbot 来验证该问题，但在未修补的客户端上与它交互会导致即时中断。

telegram · zaihuapd · 7月24日 15:06

**背景**: 零点击漏洞是一种严重的安全缺陷，攻击者可以在不需要受害者点击链接或打开文件的情况下远程执行攻击。在这种情况下，它表现为内存耗尽攻击，这是一种拒绝服务（DoS）攻击，目标被大量数据淹没，导致其分配所有可用的 RAM，从而引发内存耗尽（OOM）错误和随后的崩溃。
